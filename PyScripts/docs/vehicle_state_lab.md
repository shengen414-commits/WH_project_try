# 车辆状态观察、安装与执行器标定

## 本阶段的交付与边界

主 Dashboard「车辆控制 → 状态估计与执行器标定」进入 `/vehicle-lab`。
这里实现了可回放的直线小角度状态估计、传感器联合观察、人工测量的前轮转角表、相机地面标定工具和后续控制接口。
观察层运行在 Orange Pi，不向舵机发送自动纠偏指令。后续高速闭环的固定周期估计/控制仍应下沉到 ESP32，不能把网页轮询当实时控制。

当前尺寸按用户要求全部留空；MPU6050 已确认 Z 朝下，所以默认 `imu_yaw_sign=-1`；X/Y 完整安装方向未确认，`imu_axes=null`。
缺少标定时显示原始数据和缺失项目，不使用默认车轮直径、编码器分辨率、探头间距或图像像素来冒充 SI 单位状态。

本模型不估计横向速度、不补偿明显侧滑、不输出绝对航向，不是已经实车验证的高速 LQR。
`valid` 只表示当前观测和模型内部不确定度符合观察条件；`control_permitted` 永远为 `false`。

## 更新和启动

1. 重新编译、烧录正常 `esp32dev` 固件，包含新增的 `imu_sensor.cpp`；`servo_demo` 不提供联合观察协议。
2. 完整更新 `PyScripts/vehicle_state/`、新页面/静态资源及 Dashboard 后台，重启后台并刷新网页。
3. 仍然只允许 Dashboard 打开 ESP32 串口；不要同时运行串口监视器或独立相机 demo。
4. 从测试台启动联合观察，等「固件已确认」和时钟同步。保持整车静止至少2秒进行校零。
5. 手推整车、横向移动胶带，观察 CH1～CH8、编码器计数和横摆方向。
6. 退出观察，收到正常 ENC 数据确认后恢复其他模式。关闭浏览器不会退出测试。

U 观察模式会关闭已有自动转向并按原逻辑回中，锁定 ESC 中位，不主动绑定舵机 PWM。
可以手推车辆检测编码器；不能在 U 模式下通过油门让车行驶。

## 三种传感器安装

统一车身右手坐标：X 朝前，Y 朝左，Z 朝上；状态参考点为后轮轴中点。
所有安装尺寸都使用这个参考点，不能混用车头、相机或重心为原点。

### MPU6050

- 固定在主车架刚性部位、尽量接近重心，避免安装在舵机支架、松动插接板或软弹性结构上。
- 现在 Z 朝下可以保留，换算横摆使用 `r=-corrected_gz*pi/180`。
- 板面应近似水平、Z轴近似竖直。若安装倾斜明显，需要完整安装旋转矩阵，不能只对gz反号；当前偏航适配器面向水平安装。
- 将整车从上方看逆时针转动，即车头向左，测试台显示的横摆角速度应为正。
- X/Y 箭头方向未知时，保留 `imu_axes=null`。此时加速度仅显示传感器原始轴数据，不输出车身横向加速度。
- 例如**只有确认**传感器 X 朝前、Y 朝右、Z 朝下时，完整映射才可填 `[1,-2,-3]`。
  单独使用 `[1,2,-3]` 是左手坐标，程序会拒绝。
- 保持 I²C 线短、供电与地可靠，布线远离大电流电机线；倒插连接也需要机械固定，不能仅靠松动插针承受振动。
- 本版采样100Hz、硬件陀螺低通20Hz，串口观察约50Hz。读数时间是软件读寄存器完成时间，
  仍包含传感器采样相位和低通群延迟，不能宣称硬件同步；进入高速控制前应实测/建模这部分延迟。

MPU6050 的硬件量程和滤波参见 [TDK 产品资料](https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/mpu-6000-datasheet1.pdf)。

### 八路巡线模块

- 横跨车身，CH1 在车左，CH8 在车右；CH4/CH5 中点对准车身纵向中线。
- 优先装在前轴附近或略前方，底面朝向地面，避开轮胎、转向连杆和车架阴影。
- 使用可调且刚性的离地支架。具体高度以本模块在实际黑胶带/木板上的稳定区间为准，不能套用其他红外模块的高度。
- 在实际灯光下逐个探头扫过胶带，检查逻辑命中位与实物亮灯一致；不要靠反转舵机方向补偿错误的黑白极性。
- 测量 `line_pitch_m`（相邻探头中心距）、`line_x_m`（距后轴向前的距离）、`line_y_m`（模块中心向左的偏移）。
  居中安装也要测量/确认后明确填0；空值表示未知。

直线小角度观测关系是 `offset_left + line_y = -e_y - line_x*e_heading`。
这避免将车头探头的偏差直接当作后轴参考点偏差。

### OV9281

- 使用车架中线附近的刚性支架朝前下方拍摄地面，让近处胶带和前方一段胶带同时进入画面。
- 可先按约20～35cm高度、向下约25～45°试装，再根据实际镜头视场调整。这是试装建议，不是本型号保证的光学参数或程序标定值。
- 让地平线和无关背景尽量位于检测区域之外；避免胶带反光和运动模糊，曝光时间需结合车速实测。
- 相机地面测量使用同一个后轴原点，地面坐标 X前/Y左，单位米。
- 改安装角度、镜头、分辨率后重新标定。地面平面假设受车架俯仰/侧倾影响，后续需要评估姿态变化。
- 预瞄距离至少覆盖 `车速×总延迟`，再留出车辆纠偏距离。不能只按相机标称FPS决定高速可行性。

地面映射方法参见 [OpenCV 单应性说明](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)。

## 安装尺寸填写

测试台输入框使用 mm，保存文件使用 m。
编码器比例推荐在直线路面手推已测量距离，使用 `meters_per_count=距离m/计数变化绝对值`，重复测量几次。
同时确认向前手推时计数增加还是减少，分别填写 `encoder_sign=+1/-1`。
不能把电机标称 PPR 直接当车轮每圈计数，传动比和当前中断计数方式必须考虑。

文件位于 `<CAR_RECORDS_DIR>/Vehicle_Calibration/profile.json`，默认是项目 `Car_Records/` 下。
使用版本号、完整校验和原子替换；写入失败保留原配置。
观察运行中禁止修改安装参数，避免把新旧坐标/单位混入同一段估计。

## 前轮转角标定

普通三线 DS3120 没有外部轴角回传，软件不能自动知道实际车轮角度。
现有「保存直行中位」负责 ESP32 NVS 中的直行脉宽；这里记录的是之后的 `PWM → 前轮实际转角` 表。

1. 退出联合观察，在主 Dashboard 进入手动舵机模式，完成机械对中/直行中位保存。
2. 保持动力中位，用±5μs小步调整，先确认机构两侧都不卡住。
3. 待轮子停稳，用量角器、转角盘或经过标定的外部测量工具测前轮等效转角，左正右负。
   不是舵机摇臂角度。两前轮不同时，可记录左右前轮方向的平均值作为小角度等效转角，并保持测量方法一致。
4. 在测试台填写角度，点击记录。程序只取手动模式已确认的当前脉宽，拒绝待确认、过期或正在切换的命令。
5. 至少记录左右和中位3点，建议5～7点。直行约0°，两侧各至少3°，转角随PWM必须严格单调。
6. 从相同方向接近各测点，另外检查反向回差、不同负载下的重复性。程序不会把这些手工静态测点当作已辨识的舵机时间常数。
7. 「仅计算脉宽」用于验证插值，不会发送硬件指令；超出实测角度范围拒绝外推。

如果重新保存直行中位或调整连杆，旧转角表失效，需要重新记录。
表只覆盖实测区间，不会扩大固件±300μs边界，也不等于允许高速下使用满行程。
进入后续闭环前，还应实测加载后的舵机响应时间、回差和PWM变化速率上限；目前150μs/s的自动转向限制未在本阶段放宽。

## 相机地面标定

输入点文件必须包含实际相机内参 `camera_matrix`、畸变系数 `dist_coeffs`、实际 `image_size` 和图像/地面点对应表。
不能把未知畸变默认填为零。

格式（`u/v/X/Y` 要替换为数字，不能直接作为标定文件使用）：

```text
{
  "image_size": [实际宽, 实际高],
  "camera_matrix": 实测3×3内参,
  "dist_coeffs": 实测畸变系数数组,
  "latency_ms": null,
  "pairs": [
    {"image": [u, v], "ground": [X米, Y米], "validation": false},
    ...至少6个覆盖区域的训练点...,
    {"image": [u, v], "ground": [X米, Y米], "validation": true},
    ...至少2个未参与拟合的独立验证点...
  ]
}
```

```bash
python -m PyScripts.calibrate_ground_camera --input points.json --output camera_ground.json
```

工具先去畸变、求平面映射，再用独立点验证；最大误差超过20mm拒绝输出。
导入生成的JSON到测试台。只有覆盖标定区域、纵向跨度足够且拟合可靠的胶带点才会进入融合。
主 Dashboard 相机由同一个采集线程发布帧号、单调读帧时间和原始帧，视觉线程不重复打开相机。

`latency_ms` 是**曝光到主机读帧完成**的实测估计延迟。未知时保留null，此时只预览像素结果，不进行米/弧度视觉融合。
用独立时间基准或周期闪光事件实测平均延迟和抖动，并记录测试条件；不能把检测算法耗时当作整条相机延迟。
剩余时延抖动仍需在高速控制设计中纳入。

## 估计器和融合边界

```text
ESP32 imu_sensor.* → 独立采集接口
ESP32 serial_transport.cpp → U观察流 / 时间探测 / 动力互锁
Orange Pi vehicle_state/clock.py → 带往返误差界限的设备时间映射
vehicle_state/contracts.py → SI单位不可变观测对象
vehicle_state/vision.py → 图像到地面适配，不控制硬件
vehicle_state/estimator.py → 直线小角度KF及延迟事件重放
vehicle_state/profile.py → 安装参数、前轮转角插值、原子保存
vehicle_state/service.py → 单串口观察会话/共享相机/记录协调
vehicle_state/web.py → 测试HTTP入口
```

估计状态为 `[e_y, e_heading, residual_gyro_bias]`。
运动预测使用编码器速度和已校零的横摆角速度；不对加速度二次积分。
相机对横向/方向误差进行带相关协方差的联合更新，巡线对安装点偏差进行标量更新。
保留约0.6秒有界历史，最多接收0.5秒以内的延迟观测，插入后重算所有后续观测。
重复序号、不合法协方差、过期输入、明显创新异常都会拒绝；断线、设备重启、数据过期或缺失标定会失效。

状态协方差只表达本模型的内部不确定度，不代表已经涵盖胶带测量系统误差、侧滑、车架振动和相机支架形变。
|方向偏差|超过0.35rad或不确定度过大，不标记为有效。

后续融合/控制可以使用：

```python
from PyScripts.vehicle_state.contracts import VisionObservation

# timestamp 是同一 Orange Pi 的 time.monotonic() 时域，已减去曝光→读帧延迟。
lab.submit_vision(VisionObservation(timestamp, sequence, error_m, heading_rad,
                                    (var_y, cov_y_heading, cov_y_heading, var_heading), confidence))
state = lab.status()['state']
# 未来控制器消费 state；本阶段 control_permitted 恒为False。
# 未来执行器适配器调用 angle_to_pulse(profile, angle_rad, firmware_confirmed_center)。
```

高速控制迁移到ESP32时，保持相同坐标、单位、采样时刻和有效性语义，增加横向动力学/舵机动态及固定周期调度。
不要把网页JSON请求作为100Hz闭环，也不要把当前空缺的 `lateral_speed_m_s` 填零送入四状态LQR。

## 测试接口

| 接口 | 用途 |
|---|---|
| `GET /vehicle-lab/status` | 原始值、状态、协方差、有效性、标定缺项和时钟误差界限 |
| `POST /vehicle-lab/command` | `{"action":"start/stop/zero"}`，依赖固件反馈确认 |
| `POST /vehicle-lab/profile` | `geometry`完整对象和/或工具生成的`camera`对象 |
| `POST /vehicle-lab/actuator/point` | `{"angle_deg":实测值}`，只记录固件确认的手动脉宽 |
| `POST /vehicle-lab/actuator/preview` | 转角→PWM纯计算，不发硬件 |
| `POST /vehicle-lab/vision` | 注入`VisionObservation`字段，仅用于观察/后续接入 |
| `GET /vehicle-lab/trace` | 观察退出并记录完成后下载本轮JSONL |

固件串口：`U`开始联合观察，`Z`静止校零，`R`退出，`E`保留急停，`!数字ID`请求`[SYNC],ID,millis`。
新增 `[OBS],seq,ms,count,raw_mask,line_mask,line_ms,pwm,center,low,high`、`[LAB],ms,ready,calibrating` 和 `[LAB_MSG]`。
`[IMU]`继续沿用已有字段/单位，便于复用解析器。发生串口拥塞时丢上报、不阻塞采集和控制；OBS序号缺口用于诊断。

测试日志在 `<CAR_RECORDS_DIR>/State_Records/*.jsonl`，含标定快照、原始串口、观测对象和状态快照。
写盘使用有界队列，丢弃计数和写盘错误可查看。退出后可离线回放：

```bash
python -m PyScripts.replay_vehicle_state state_实际时间.jsonl --output replay.csv
```

## 延迟与存储隔离

- 串口接收线程只向联合观察的输入队列投递，不运行状态估计或写盘。队列最多64条；满时丢最旧项。
  排队超过100ms的输入直接丢弃，并清空估计历史后重新建立状态，避免把积压数据作为实时位置。
  `/vehicle-lab/vision` 的 `accepted/queued` 只表示通过基本检查并入队，后续仍可能因过期或异常被拒绝。
- 相机检测、状态处理、时钟探测和日志存储分别运行。检测完成时读帧已超过250ms则不提交结果；
  有效视觉观测先入队，再压缩网页预览。时钟请求的发送时间在取得串口写锁后记录。
- JSONL 文件创建、首行、周期flush和退出fsync都在存储线程执行，队列最多1024项/2MiB。
  存储拥塞会产生明确的 `record.drops/error`，不会让接收线程等待磁盘；退出后仍须等 `record.done` 才能下载。
- 网页状态及 `/vehicle-lab/status` 提供 `latency`：输入队列深度、最近/最大排队和处理耗时、处理中耗时、
  过期/溢出丢弃数、相机检测和预览压缩耗时。`record` 提供排队字节数、积压年龄及磁盘操作耗时。
  处理线程忙时返回失效的缓存状态，避免网页跟着等待，也不会将缓存状态标为可用。
- 标定原子保存的磁盘同步不再持有参数读取锁；保存提交成功前，读者继续读取上一份完整标定。
  速度CSV创建不持有串口接收用的记录锁，计时从文件准备完成开始。相机图片及回放目录由存储线程创建。
- 两分钟回放的配置/快照取锁最多等50ms；磁盘忙时提示重试。快照等待超时不再二次等待磁盘锁，
  未完成的缓存引用交给写盘线程释放。回放关闭有界等待，操作系统中卡住的磁盘调用不能被Python强行中断。
- 压力UDP接收与 `.dat/.index.csv` 存储分线程，队列最多128个数据报/4MiB（另加一个正在写入的数据报）。
  每0.5秒flush，接收时戳在入队前保存；状态中的 `storage.frames_saved/bytes_saved` 与 `frames_received` 分别统计。
  队列满或写盘失败会报错并请求停止压力采集，保留已有文件。关闭时等待队列排空及文件关闭，超过2秒提示仍在保存、
  保留文件占用，后续可重试关闭；元数据写入不持有控制器锁。`storage` 同时保存进压力元数据。
- ESP32联合观察的OBS/IMU各50Hz、相位错开10ms；发送缓冲满时跳过当前时隙，禁止每轮循环重新格式化重试。
  后台串口逐行打印默认关闭，即使开启也通过有界异步输出队列。

以上是软件隔离和拥塞处理，不代表硬实时保证。相机曝光/USB缓冲、传感器滤波、主机调度和实际存储速度仍需在Orange Pi上测量。
更新时同步 `PyScripts` 与 `mps4264_app`，重启Dashboard，并重新烧录 `esp32dev` 固件使发送调度修复生效。

## 实车验收顺序

1. 不接管舵机：静止两秒校零，检查校零成功及正负方向；断线/遮挡后状态必须失效。
2. 检查八个探头顺序、单条胶带有效、全黑/丢线/分离线段无效；不要用平均中心掩盖错误命中。
3. 实测距离和计数比，确认向前速度为正、停止后速度回零；缺尺寸时不显示伪车速。
4. 完成静态转角表、重复性和左右机械余量检查。
5. 地面独立标尺点验证相机误差、测延迟、遮挡相机和加入延迟回放测试。
6. 记录低速手推数据，对照实测误差检查估计与不确定度，再决定何时接入低速闭环。
