# 高速直线行驶智能小车 —— 完整实现方案

## 一、任务理解

目标一句话概括：**用「前轮阿克曼转向 + 摄像头/灰度寻迹」实现小车在高速下稳定直线行驶。**

拆成三个子目标：

| 子目标 | 作用 | 关键点 |
|---|---|---|
| 阿克曼几何转向 | 机械/运动学基础 | 内轮转角>外轮，转向时四轮纯滚动不侧滑 |
| 摄像头寻迹 | 外层目标给定（要走哪条线、离中线多远） | 提供「目标横摆角速度 r_ref」或横向/航向偏差 |
| 高速直线稳定 | **核心难点** | 靠陀螺仪内环反馈抗扰动 |

**核心矛盾**：高速下如果只用「摄像头 → 舵机」开环控制，会因为视觉延迟（几十 ms）＋舵机滞后，产生「蛇形/甩尾」，根本走不直。这正是 GyroM5 参考项目的价值所在——**横摆角速度（yaw rate）陀螺仪内环以 100–400Hz 高频实时校正**，视觉只负责给目标，这才是高速走直的关键。

## 二、现状盘点（基于仓库 + 参考仓库源码）

**现有仓库 `WH_project_try` 已具备：**
- ESP32 + PlatformIO（Arduino 框架），`esp32dev`，`ESP32Servo` 库
- `esc_control`：电调 PWM（GPIO14）、RC 接收机抢占（D27 中断测脉宽）、急停 `E`、助推 `B`、油门 `T`、WEB/RC 双模式状态机
- `encoder`：编码器测速（`pulseCount`）
- `sd_logger`：SD 日志 + 串口指令分发
- Python 脚本：OpenCV 摄像头检测、MPU6050 可视化、SD 读写

**已有硬件**：ESP32、MPU6050、DS3120 舵机（20KG 单轴）、8 路灰度、电调+无刷电机、编码器。

**缺（本次要补的）**：① 陀螺仪 yaw-rate PID 内环 ② 阿克曼转向标定 ③ 视觉→横摆角速度外环 ④ 串级融合 ⑤ 舵机驱动。

## 三、参考项目关键结论

**GyroM5（最重要参考）** —— 漂移 RC 车转向陀螺仪，控制核心从源码提取：

```
内环 PID（QuickPID 库）：
  Setpoint(SP) = CH1_USEC - MEAN      // 转向指令相对中位(1500us)的偏差
  Input(PV)    = K_g × yaw_rate       // 实测横摆角速度 × 陀螺增益
  Output       = MEAN + PID(SP - PV)  // 舵机 PWM = 中位 + 修正量
```

即内部误差 `e = SP - PV = (转向指令偏差) - K_g × yaw_rate`，和任务文档写的 `error = r_ref - r·K_g` 一致。**当转向指令回中（SP=1500）时，PID 强制 `yaw_rate → 0`，这就是「外力扰动下舵机自动回正保持直线」的机理。** 默认参数：`KP=50, KI=10, KD=5, KG=50`，PWM 频率 50–400Hz，PID 周期与 PWM 同步，Mahony AHRS 估算姿态并自动检测竖直轴。

**其他参考**：
- `Wheel-legged-autocar`：MPU6050 姿态解算/平衡的经验可复用到 IMU 标定
- `allenb24/Autonomous-Vehicle`：**OpenMV 双摄像头 + 实时车道检测**，是「车载视觉不依赖 PC」的落地范式
- `caipeide/autorace`：竞赛级速度控制、赛道寻迹调参思路

## 四、总体架构：串级（Cascade）控制

```
┌──────────── 外层(慢, ~10–30Hz)：寻迹 ────────────┐
│ 摄像头/灰度 → 横向偏差 e_lat、航向偏差 e_head      │
│            → r_ref = K_lat·e_lat + K_head·e_head │  (目标横摆角速度)
└───────────────────────┬──────────────────────────┘
                        ↓ r_ref
┌──────────── 内层(快, 100–400Hz)：陀螺仪稳定 ─────┐
│ e = r_ref − r_meas(陀螺仪Z,去偏+滤波)             │
│ u = Kp·e + Ki·∫e + Kd·ė   (QuickPID)             │
│ 舵机PWM = 1500 + u   (限幅 1000–2000)             │
└──────────────────────────────────────────────────┘
                        ↓
                  阿克曼转向连杆 → 前轮转角
```

**两条路径可切换**（复用已有的 RC 抢占逻辑）：
- **手动 RC**：`r_ref` 来自遥控转向通道（等价 GyroM5 原版，回中即走直线）
- **自动寻迹**：`r_ref` 来自视觉/灰度外环

**速度环（并列）**：编码器测速 → 速度 PID → 电调油门，高速直线时恒速更稳。已有 `encoder` + `esc_control`，只需加一个 `speed_pid`。

## 五、分模块实现方案

### 5.1 阿克曼转向（机械 + 标定）

- DS3120 舵机 → 转向臂 → 横拉杆 → 左右前轮，满足 `cot δ_o − cot δ_i = 轮距/轴距`。
- **标定**（比几何公式更实用）：先上电让舵机输出 1500us 中位，机械调前轮至正前方；再扫 1000/2000us 记录左右极限角，拟合「PWM↔转角」线性表（通常可用 `angle = k·(pwm−1500)` 近似，存入参数）。
- 20KG 力矩足够在高速下**抗回正力矩**，这是选它的意义。

### 5.2 MPU6050 读取与标定（内环测量源）

- 用 I2C（默认 SDA=21 / SCL=22）。**只取陀螺仪 Z 轴**（yaw），安装保证 Z 轴竖直（可参考 GyroM5 的 AXIS 自动检测，或直接固定）。
- **零点标定**：静止采集 N 次陀螺 Z 取均值作为 bias，运行时 `r_meas = raw − bias`。
- **低通滤波**：一阶 `r_f = α·r_new + (1−α)·r_old`（α≈0.1–0.2），抑制振动噪声。
- 仅做 yaw-rate 反馈不需要完整 AHRS；若要做绝对航向/漂移抑制再上 Mahony（GyroM5 的 `M5StackAHRS` 可直接移植）。

### 5.3 陀螺仪内环 PID（核心，直接移植 GyroM5）

新建 `steering_control` 模块，复用 `QuickPID`（加入 `lib_deps`）：

```cpp
// 每 2.5ms(400Hz) 或与舵机 PWM 同步执行一次
float r_meas = getFilteredYawRate();      // 去偏+低通后的 yaw rate (deg/s)
float e      = r_ref - r_meas * K_g;      // K_g 陀螺增益(初值1.0)
float u      = qpid.Compute(e);           // 内部 Kp/Ki/Kd
int   servo  = constrain(1500 + u, 1000, 2000);
steeringServo.writeMicroseconds(servo);
```

- 起始参数沿用 GyroM5 默认：`KP=50, KI=10, KD=5, KG=50`（其内部做了 /50、/250、/5000 的归一化，移植时注意量纲，直接用 QuickPID 原始 Kp/Ki/Kd 建议从 `Kp=1.0, Ki=0.0, Kd=0.0` 起调，Ki/Kd 再慢慢加）。
- 抗积分饱和：`SetAntiWindupMode(iAwClamp)`（GyroM5 已做）。

### 5.4 摄像头寻迹外环

**部署二选一（这是最大的架构分叉）**：

| 方案 | 延迟 | 车载性 | 适用 |
|---|---|---|---|
| A. PC+OpenCV（现有 PyScripts） | 高，需串口/无线回传 | 否，有牵引 | 开发调试、原理验证 |
| B. **OpenMV 车载**（推荐，参考 allenb24） | 低 | 是 | 最终高速自主 |
| C. ESP32-CAM | 中，算力受限需降采样 | 是，便宜 | 预算敏感 |

外环算法（无论 A/B/C 一致）：

```python
# 1. 灰度化 + 阈值/颜色掩膜 → 提取车道线
# 2. 拟合直线，求：
lateral_error = lane_center_x - frame_center_x   # 横向偏差(像素)
heading_error = 车道线与竖直方向的夹角            # 航向偏差
# 3. 合成目标横摆角速度
r_ref = K_lat * lateral_error + K_head * heading_error   # 一个 P 型外环
# 4. 通过 UART 发送 r_ref 给 ESP32 内环
```

- 直线场景下 `heading_error≈0`，主要靠 `lateral_error` 把车拉回中线；`r_ref` 的物理含义是「让车朝中线转多快」。
- 注意外环输出要**限幅**，防止目标横摆角速度过大导致内环打满舵翻车。

### 5.5 8 路灰度（外环补充 / 高速本地跟踪）

- Yahboom 8 路灰度直接给出**车底横向偏差**（哪几路压线），无需图像处理、延迟极低，适合高速下做「最后一道」本地校正。
- 可复用同一内环：`lateral_error = Σ(i·sensor_i)/Σsensor_i − 中心` → `r_ref`。
- 建议：**摄像头负责前瞻（远处路线），灰度负责近端精校**，二者按速度加权融合。

### 5.6 速度环 + 电调

- `encoder` 已有，加 `speed_pid`：`throttle = 1500 + Kp·(v_ref − v_meas) + …`，喂给现有 `setESCThrottle()`。
- 高速直线目标速度可设定（如 2–3 m/s），速度环恒定后直线更稳。

### 5.7 主循环调度（无阻塞）

```cpp
setup():
  初始化 I2C+MPU6050、舵机(PWM 50Hz)、电调、编码器、灰度、串口/UART
  陀螺零偏标定、舵机中位标定

loop():
  1. 读 RC/串口 → 判断 WEB/RC/AUTO 模式   (复用 updateESC)
  2. 读摄像头/灰度 → 更新 r_ref            (AUTO 模式，低频节流)
  3. 每 2.5ms: 读陀螺 → 内环 PID → 写舵机  (定时器/微秒节流)
  4. 速度环: 读编码器 → PID → 写电调
  5. 日志/SD + 串口遥测
```

## 六、实施步骤（建议里程碑）

1. **M1 硬件走线**：接好舵机、MPU6050、电调、编码器、灰度；确认引脚分配（现有 ESC=14、RC=27，I2C=21/22，舵机/灰度另定并核对）。
2. **M2 舵机标定**：中位对正前轮 + 左右极限扫描，建立 PWM↔转角关系。
3. **M3 陀螺内环打通（手动模式）**：移植 GyroM5 PID，遥控转向，验证「回中走直线、外力扰动自动回正」——这是整个方案的地基，务必先跑通再上视觉。
4. **M4 速度环**：编码器恒速，低速直线跑稳。
5. **M5 视觉外环（先 PC 验证）**：OpenCV 直线拟合 → r_ref 串口下发，验证串级寻迹走直线。
6. **M6 灰度外环**：8 路灰度本地校正，与视觉融合。
7. **M7 车载化 + 高速调参**：视觉迁到 OpenMV/ESP32-CAM，提速度，逐项调 Kp/Ki/Kd/Kg 与 r_ref 限幅。

## 七、调参与风险

- **调参顺序**：先 `K_g`（陀螺灵敏度）→ 再 `Kp`（响应）→ 需要消稳态再 `Ki` → 需要抑制振荡再加 `Kd`。避免一开始 Ki/Kd 过大引起低频摆动。
- **内环频率**：至少 100Hz，越高越好（舵机本身支持到 ~330Hz，DS3120 可测）。
- **主要风险**：
  - 舵机虚位/连杆旷量 → 直线左右摆；用 20KG 舵机 + 减小旷量解决。
  - 陀螺零偏没标好 → 缓慢漂移；上电标定 + 低通。
  - 视觉延迟 → 高速蛇形；把视觉降为外环低频、灰度做近端精校、内环高频兜底。
  - 外环 r_ref 过大 → 翻车；严格限幅 + 转向角软限位。

---

**一句话总结方案**：以「**陀螺仪横摆角速度 PID 内环（移植 GyroM5）**」为高速直线稳定的地基，以「**阿克曼转向 + 舵机标定**」为执行层，以「**摄像头前瞻寻迹 + 8 路灰度近端精校**」为外环目标给定，用**串级控制**把三者串起来，先手动内环跑通、再叠加视觉、最后车载化提速度。
