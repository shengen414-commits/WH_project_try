# steering_gyro 外环与遥控接入说明

> 对应工程目录：`steering_gyro/`
> 本文说明在「陀螺仪内环」基础上新增的三个 **r_ref（目标横摆角速度）来源**：RC 遥控转向、8 路灰度巡线、摄像头寻迹，以及它们的实现逻辑、接线、使用方法、验证方法。

---

## 一、总体：三种 r_ref 来源与模式

内环（陀螺 yaw-rate PID → 舵机）保持不变，`r_ref` 由模式决定：

| 模式 | 值 | r_ref 来源 | 用途 |
|---|---|---|---|
| `MODE_MANUAL` | 0 | 串口 `R <deg/s>`（手动或 PC 摄像头流式下发） | 测试 / 摄像头寻迹 |
| `MODE_RC` | 1 | RC 接收机转向通道 CH1 → 目标横摆角速度 | 手动遥控模式 |
| `MODE_GRAY` | 2 | 8 路灰度横向偏差 → 目标横摆角速度 | 车载自动寻迹 |

数据流：

```
RC 转向 CH1 ──映射──┐
灰度 8 路 ──横向偏差×K──┼──> r_ref ──> 内环 PID ──> 舵机
摄像头(PC) ──流式 R ────┘
```

## 二、RC 遥控转向通道（`rc_steering`）

### 2.1 作用与原理

把遥控器转向摇杆的 PWM 信号（1000~2000us，中位 1500us）**映射为目标横摆角速度**。这和参考项目 GyroM5 的「转向指令作设定值、陀螺测横摆角速度作反馈」完全一致：摇杆回中时 `r_ref=0`，内环强制车身 `yaw_rate→0`，即遥控回中就走直线、受外力自动回正。

映射公式（`rc_steering.cpp:update()`）：

```
r_ref = (脉宽 − 1500) × (maxYawRate / 500)
       // 满舵 ±500us → ±maxYawRate(默认 180°/s)
```

### 2.2 实现要点

- **中断测脉宽**：`attachInterrupt(pin, isr, CHANGE)` 双边沿中断，测上升沿到下降沿的高电平时间，滤除 900~2100us 之外的毛刺（与现有 `esc_control.cpp` 油门读取同理）。
- **断连保护**：超过 100ms 无有效脉冲 → 判定断连，`r_ref=0`（防止接收机掉线导致失控）。
- **非阻塞**：`update()` 只读中断维护的脉宽并换算，不阻塞内环。

### 2.3 接线与使用

- 接线：RC 接收机转向通道(CH1)信号线 → GPIO26（`main.cpp` 顶部 `RC_STEER_PIN`）。
- 使用：上电发 `M 1` 切到 RC 模式，发 `S` 使能，即可用遥控器转向。

## 三、8 路灰度巡线（`grayscale`）

### 3.1 硬件协议（已核实官方例程）

- 通信：I2C，地址 **0x12**，寄存器 **0x30**，读 **1 字节**。
- 数据含义：返回字节 `bit7=x1 … bit0=x8`，每位表示对应通道是否压线。
- 时序：写寄存器后需等约 **10ms** 再读（官方 `delay(10)`，给模块处理时间）。

### 3.2 作用与原理

由 8 个通道的「横向重心」算出车相对黑线的横向偏差，再用 P 控制转成目标横摆角速度：

```
横向偏差 lateralError = Σ(pos_i × active_i) / Σ(active_i)      // pos: x1=-3.5 … x8=+3.5
r_ref = kLat × lateralError   (限幅 ±maxYawRate)
```

- 无通道压线（丢线）时 `lateralError=0` → `r_ref=0`，车保持直线直到找回线。
- 灰度是**车载本地**传感器，延迟远低于摄像头，适合高速下做近端精校。

### 3.3 实现要点

- **非阻塞读取**：用状态机 `IDLE →(写寄存器)→ WAITING →(等10ms)→ 读数据`，期间不占用 CPU，因此可以放在 200Hz 内环里同步调用，实际约每 15ms 完成一次读取（≈66Hz）。
- **极性可配**：`setActiveHigh(bool)`，默认 `1=压线`；若你的模块反过来，设 `false`。

### 3.4 接线与使用

- 接线：灰度模块 SDA/SCL 并到 I2C 总线（与 MPU6050 同一条，SDA=21/SCL=22），VCC=5V（或按模块要求）、共地。
- 使用：上电发 `M 2` 切到灰度模式，发 `S` 使能。
- 调增益：`L <kLat>`（默认 30，deg/s per channel）；方向反了就设负值 `L -30`。

## 四、摄像头寻迹（`camera_line_follow.py`，PC 端）

### 4.1 作用与原理

摄像头在 PC 端用 OpenCV 检测车道线，算出横向/航向偏差，合成 `r_ref`，通过串口流式下发给 ESP32（对应 `MODE_MANUAL` 模式）。这是方案里「先 PC 验证、后车载化」的第一步。

```
r_ref = kLat × lateral_error + kHead × heading_error   (限幅 ±maxYaw)
```

- `lateral_error`（像素）：线质心 x 相对画面中心的偏差，正值=线在右侧。
- `heading_error`（度）：拟合直线与竖直方向的夹角（`arctan2(vx,vy)`）。

### 4.2 实现要点

- 取反 + 大津阈值把「深色线在浅色背景」提成白线；只取画面下方 40% 作感兴趣区。
- `cv2.fitLine` 拟合直线方向求航向偏差；线像素质心求横向偏差。
- 固定频率（默认 25Hz）以 `R <r_ref>\n` 下发；丢线时下发 `R 0`（保持直线）。
- 画面实时显示拟合线、质心、中线，便于调试。

### 4.3 环境与使用

```bash
pip install opencv-python pyserial numpy

# 只调画面(不发串口)
python camera_line_follow.py --cam 0 --no-send

# 正式下发到 ESP32(先确认端口)
python camera_line_follow.py --port COM10 --cam 0
```

主要参数（命令行）：`--k-lat`（默认 0.15）、`--k-head`（默认 0.8）、`--max-yaw`（默认 120）、`--hz`（默认 25）。

## 五、新增串口命令与遥测

### 5.1 命令（在原有基础上新增）

| 命令 | 作用 |
|---|---|
| `M <0/1/2>` | 切换模式：0 手动/摄像头、1 RC、2 灰度 |
| `L <kLat>` | 设置灰度横向增益（可负） |
| `R <deg/s>` | 手动目标横摆角速度（**静默**，供摄像头高频流式调用） |

原有命令 `P/I/D/G/S/C/?` 不变。

### 5.2 遥测格式（20Hz 输出）

```
mode, r_ref, r_meas, lateral_error, servo_pwm
0,    0.0,    0.3,      0.00,          1500
```

- `r_ref`：当前目标横摆角速度；`r_meas`：实测横摆角速度；`lateral_error`：灰度横向偏差（灰度模式才有意义）；`servo_pwm`：舵机实际输出。

## 六、验证方法（分步，含判据）

### 6.1 先验证内环（前置，参考上份说明）
确认内环「掰头反向回正」正常后，再做外环。

### 6.2 验证 RC 模式

1. 接好 RC 接收机转向通道 → 发 `M 1`、`S`。
2. 摇杆回中，看遥测第 2 列 `r_ref` 应 ≈ 0。
3. 摇杆左右打，`r_ref` 应随之正负变化、满舵接近 ±180。
4. **判据**：拨动摇杆车随动转向；松手回中后车恢复直线；断开接收机，`r_ref` 自动归 0（断连保护）。

### 6.3 验证灰度模式

1. 接好灰度模块，发 `M 2`、`S`。
2. 把车放在黑线上，看遥测第 4 列 `lateral_error` 和 `raw`（可临时打印）。
3. 手推车偏移黑线，`lateral_error` 应随之变化、符号正确。
4. **判据**：车压线中心时误差≈0；偏左/偏右误差符号相反；离线下发 `r_ref=0`。
5. 若方向反了，发 `L -30` 翻转；若「压线=0」极性反了，改代码里 `setActiveHigh(false)`。

### 6.4 验证摄像头模式

1. 先 `--no-send` 跑脚本，确认画面里拟合线与实际车道线吻合、质心位置正确。
2. 再正式下发（`--port COM10`），ESP32 保持 `M 0` + `S`。
3. **判据**：把线在画面里左右移动，遥测 `r_ref` 随偏差正负变化；车能沿线行驶。

## 七、调参

| 参数 | 作用 | 起始值 |
|---|---|---|
| RC `maxYawRate` | 满舵对应横摆角速度 | 180 |
| 灰度 `kLat` | 横向偏差→横摆角速度增益 | 30（方向错设负） |
| 摄像头 `kLat` | 横向偏差(px)→横摆角速度 | 0.15 |
| 摄像头 `kHead` | 航向偏差(°)→横摆角速度 | 0.8 |

**原则**：外环增益宜**小步慢加**，先让内环能跟上；外环过大会导致目标横摆过大、舵机打满、蛇形甚至翻车。外环输出都已限幅（灰度 ±120、摄像头 ±120）。

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 灰度读不到数据 | 地址/接线/供电 | 确认地址 0x12、I2C 共总线、模块供电 |
| 灰度方向反 | 安装方向 | `L -30` |
| 灰度「压线=0」判断错 | 极性 | 改 `setActiveHigh(false)` |
| RC 无反应 | 通道接错/未供电 | 查 GPIO26、接收机供电 |
| 接收机断开后车乱跑 | 未触发断连保护 | 确认 `update()` 在循环中被调用 |
| 摄像头 `r_ref` 一直 0 | 阈值/丢线 | 用 `--no-send` 看画面、调阈值/ROI |
| 摄像头下发后车抖 | 外环增益过大 | 减小 `--k-lat/--k-head` |

## 九、与整体方案的对应

- **M3（陀螺内环手动）** → 用 `MODE_RC` 完成，遥控回中走直线。
- **M5（视觉外环 PC 验证）** → 用 `camera_line_follow.py` + `MODE_MANUAL` 完成。
- **M6（灰度外环）** → 用 `MODE_GRAY` 完成，作为高速近端精校。
- **后续车载化** → 摄像头迁到 OpenMV/ESP32-CAM 后，把算出的 `r_ref` 用同一串口协议发给 ESP32，无需改动内环代码。
