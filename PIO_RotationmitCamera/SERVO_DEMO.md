# D12 舵机调试

正常 `esp32dev` 固件已集成舵机调试。模块源码为 `src/steering_control.cpp`，
参数在 `include/steering_control.h`。只测试舵机时仍可选择独立 `servo_demo` 环境，
两种固件共用基本舵机命令；网页精确脉宽协议仅由新版正常固件提供。旧版正常固件没有接入 demo，因此 C/L/R/A 不会控制舵机。

## Dashboard 折叠手动面板

车辆控制区的巡线按钮下新增“手动舵机调试”，默认折叠。展开本身不发送命令。

1. 烧录本次更新后的正常 `esp32dev` 固件，同步更新 Python 后台及页面，重启并刷新网页。
2. 车辆静止、油门归中后，展开面板，点击“进入手动测试”。请先结束速度、扫描阀同步及三秒多源记录；相机即时回放可继续运行。
3. 等待 ESP32 确认后，使用 `±1 / ±5 / ±10 / ±50μs`、滑杆或数值输入调整，固定范围为 **1100～1900μs**、中位 **1500μs**，即中位±400μs。滑杆放开时发送一次，数值通过“应用”或回车提交。这个范围是软件许可范围，不保证机构可以无阻碍地走到两端，应从小步开始验证。
4. 面板手动范围固定为 **1100～1900μs**，已移除上下限选择框与“应用范围”按钮；滑杆、输入、加减按钮及固件均遵守此范围。
5. 中位始终固定 **1500μs**，旧 NVS 保存的中位不再采用，也不再提供保存其他中位的按钮；若1500μs下车轮不直，请调整舵盘或连杆安装。
6. “舵机回中”保持测试模式；“归中并退出”回到1500μs并恢复正常模式，收起面板也执行归中退出。范围仅本次手动调试有效，不修改自动控制行程，再进入时仍为1100～1900μs。±10/±50等按钮超出当前范围时停在边界，不越界。

进入时会关闭自动转向并锁定电调中位，暂停编码器/巡线串口输出，避免记录缺样被误当成正常数据。退出不会重新开启自动巡线。
网页显示的是固件确认的脉宽输出，**不是舵机编码器或实测轮角**；实际左右方向由安装决定，先用小步调整确认。
未经固件确认时显示等待，最多三秒后提示超时；遇到旧固件、PWM 初始化失败、串口断开均给出状态，不把 HTTP 请求成功当成执行成功。
旧固件不支持滑杆精确设置，仍可以归中退出。关闭网页或网络断开不保证自动退出，测试后应确认“归中并退出”完成；重新打开页面可以查看并退出仍在运行的手动模式。

串口协议（正常固件 `proto=4`）：`S1505,请求编号\n` 设置脉宽，`S0000,请求编号\n` 回中，`S0001,请求编号\n` 退出，`S1100:1900,请求编号\n` 确认固定上下限（兼容请求，其他范围拒绝）。需先 `V` 进入测试。旧的 `S0002/3/4` 保存中位或逐档扩展命令会拒绝。
请求编号为非零 uint32，固件以 `[SERVO_ACK]` 回显编号、结果、当前输出和范围；页面只在确认后采用。旧固件可退出，但调整前须重新烧录 `esp32dev`；独立 `servo_demo` 不含网页精确请求协议。

### 最左、最右 PWM 与角度表

本次新增端点记录、1μs细调、转角表和曲线，直接在同一个手动面板操作：

1. 先确认1500μs下车轮直行，再在“实测前轮角度”填 `0` 并点击“记录当前 PWM＋角度”。安装调整完成后再标定，其后更改安装需重新测量。
2. 使用 `±5μs`，临近端点时使用 `±1μs`。观察实际转向，PWM 增大并不保证向左。到接近最左且机构没有顶死的位置，停稳后点“记录为最左端点”。记录采用固件确认值，不采用输入框的预览值。
3. 点击“舵机回中”，然后探测另一侧，停稳后记录“最右端点”。不要让舵机长时间顶住限位；车轮停止继续转动或持续鸣叫时立即退回几个小步，使用不顶死的端点。机械极限不是应长期保持的工作点。
4. 手动允许1100～1900μs，中位1500μs；本次更改只调整手动面板，自动控制行程仍单独配置。
5. 在不同位置，用量角工具测同一前轮相对直行方向的角度，左正右负，填写后记录。建议记录左右各2～3点与直行点。端点角度未知时可留空，先记PWM；中间角度点必须填写实测值。可在表中删除单条记录，或下载CSV。
6. 至少有左右各一个点和约0°的中位点、角度随PWM严格单调后，显示当前估计前轮角度，支持查询指定角度对应的PWM。仅做实测范围内分段插值，不外推；查询和记录不会发送舵机运动命令。±45°是角度表输入范围，显示值不是舵机角度回传。

后台要求新鲜手动状态、固件命令确认及确认后至少0.4秒；用户仍需等机构实际停稳。请求携带页面观察到的PWM及命令编号，期间输出变化时拒绝记录。

端点和实测点保存在 `Car_Records/Vehicle_Calibration/profile.json`（或配置的记录根目录），与“状态估计与执行器标定”测试台共用，后台重启后保留。中位变动时旧点失效，下一次记录清除旧表。记录端点**不自动改变**巡线行程；扩展范围中的测量允许网页只读查询，原控制/状态估计接口仍拒绝超出中位±300μs的标定表。后续应用行程或控制模型需要单独验证。



## 已经装进连杆，但上电回中会偏向一侧

断电时将车轮摆直，并不能让普通位置舵机记住这个角度。1500μs 是常用的电气中位，舵盘花键安装角度及连杆长度决定它是否对应车轮直行。

1. 若回中动作会让连杆顶死，先断电，取下舵盘或断开舵机至转向机构的连杆，不要强行扳动齿轮。
2. 让舵机在与机构分离时接收1500μs，等它停稳。安装操作先断电，尽量保持输出轴位置不变。
3. 将车轮摆直，重新对齿安装舵盘，并用可调连杆做机械校正。通过连杆长度让固定1500μs对应车轮直行。

如果同一固定脉宽下舵机持续旋转而不停止，应先确认是不是连续旋转版；连续旋转舵机的脉宽控制方向/速度，不能直接按这里的位置转向方案使用。

## 接线和供电

- 舵机信号线接 D12 / GPIO12；该线不能同时连接接收机的信号输出。
- 舵机正负极保持接收机 CH 的 `+` / `-`，按壳体符号确认，不按照片左右猜。
- 电调 BEC 的红线为接收机/舵机供电，黑线连接公共地。ESP32、接收机、电调、舵机共地。
- 舵机不要接 ESP32 3.3V 或 GPIO 取电。接收机和舵机须分别满足实测 BEC 电压要求。
- 电调输出信号仍接 D14，接收机油门信号输入仍接 D27。

常规接收机 CH 的电源针脚接公共电源，供电不依赖该 CH 是否输出 PWM。
电调 BEC 为接收机/舵机供电的通用依据：
[Hobbywing 官方说明](https://www.hobbywing.com/en/uploads/file/20250320/b9addd01e22cb5be3ff28e6f25db2a5f.pdf)。
该资料不是图片接收机的专用手册；图片不能确认 Light 的电气定义，不把舵机移到 Light 作为排障方法。
无动作时先量舵机插头的 `+` / `-` 电压（接上舵机后也测），排查插错针和压降。
有供电不代表有控制信号：舵机要同时具备正常电源、共地和 GPIO12 的 PWM。

GPIO12 是经典 ESP32 的启动配置脚。若连接 D12 后不能启动，断电后拔信号线再验证；
必要时将信号改接 GPIO18，并修改 `SteeringConfig::PIN` 后重新烧录。
不要改写 eFuse 绕过启动问题。
[Espressif GPIO12 说明](https://docs.espressif.com/projects/esp-idf/en/release-v5.4/esp32/api-reference/peripherals/sd_pullup_requirements.html)。

## 烧录正常固件

在项目根目录执行，把 COM12 换成实际串口，先关闭占用串口的后台和其他串口工具：

```powershell
pio run -d PIO_RotationmitCamera -e esp32dev -t upload --upload-port COM12
pio device monitor -p COM12 -b 115200 --filter send_on_enter
```

先把车轮架空。正常固件启动不启用舵机 PWM；首次输入 `V` 才绑定 GPIO12 并输出固定1500μs中位。
首次标定前应确认连杆不会因回中而顶死，必要时先与舵机脱开。

## 按键

大小写均可，单字符即可，CR/LF 也支持；启用 send_on_enter 时需回车发送。

| 按键 | 功能 |
|---|---|
| `V` | 进入舵机专用调试、回中，电调锁定 1500 us |
| `C` | 舵机回到固定1500μs中位，取消自动摆动 |
| `J` | 固定1500μs中位−50μs，小幅向一侧转动 |
| `K` | 固定1500μs中位＋50μs，小幅向另一侧转动 |
| `A` | 单次 中位−50 → 中位 → 中位＋50 → 中位，每步800ms |
| `X` | 取消自动摆动并回中 |
| `?` | 显示舵机命令帮助 |
| `R` | 退出调试，舵机回中，正常固件恢复数据上报和油门控制 |
| `L` / `G` | 正常固件切换为巡线调试 / 巡线原始帧模式，退出舵机测试并回中 |
| `E` | 保留原急停，舵机模式下同时取消摆动并回中 |

`C/J/K/A/X/?` 只在舵机模式有效，不占用其他模块按键。V 模式中 T/B 油门命令被丢弃，
电调模块同时禁止 RC 接管和增速；退出时不恢复进入前的旧油门/增速，需新的控制输入。
`R/L/G` 退出 V 后恢复正常油门控制，持续的遥控器动作也能重新接管。
调试模式过滤日常日志，但保留 E 急停确认。V 模式每 200 ms 输出：

```text
[SERVO] GPIO12 target=1450 us PWM=ready sweep=idle
```

这是软件目标和 PWM 绑定状态，没有机械位置反馈；不能证明舵机实际转动或供电正常。
V 模式暂停 `[ENC]` 和 `[LINE]` 串口上报，但编码器计数和巡线扫描继续运行。
L/G 模式也暂停编码器上报并过滤电调日常日志。正式行驶和同步记录前输入 `R`。

Orange Pi 网页同步区也可点击“恢复正常上报（R）”发送同一命令，无需另开串口监视器。
按钮在编码器无新鲜数据且串口已连接时显示；必须等到收到真实 `[ENC]` 才显示就绪。
恢复 R 会重新允许正常油门控制。若烧录的是独立 `servo_demo`，发送 R 不会产生编码器数据，须恢复正常固件。

建议依次输入 `V`、`C`、`J`、`C`、`K`、`C`，确认后才输入 `A`，最后输入 `R`。
J/K 实际左右方向由安装决定，仍只测试中位±50μs。网页手动允许1100～1900μs，应从小步检查机械行程；
持续嗡鸣、发热或连杆顶死时停止测试并断电，不能把软件允许的最大范围当作机构的安全范围。

## 可选独立固件

```powershell
pio run -d PIO_RotationmitCamera -e servo_demo -t upload --upload-port COM12
```

该环境上电直接进入舵机调试（回中但不自动摆动），D14 持续输出中位，不运行编码器、巡线和 RC 接管。
`R` 关闭舵机调试，`V` 重新进入；独立固件不识别 L/G，不恢复行驶功能。
测试完必须重新烧录 `esp32dev` 才能使用小车网页和速度记录。
